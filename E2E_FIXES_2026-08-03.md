## What actually changed

**One vocabulary, two runtimes.** `src/senaite/pfas/instrument_columns.py` is
now the single definition of what an instrument column can mean. Import Studio's
purpose list had drifted into a strict *subset* of the importer's column map, so
`Reporting Limit` and `Expected Ion Ratios` — the columns the BLoQ qualifier and
the ion-ratio check depend on — could not be mapped at all. Zope imports the
module directly; the worker reads the same file through a bind mount.

**One vendor detector.** The pipeline no longer detects anything: it sends the
file's headers and SENAITE, which owns `_detect_vendor_py27`, resolves them.
`native` also joined detection instead of being a fallback the scorer skipped —
it now wins at confidence 100 where it previously lost to `sciex` on incidental
column overlap. The version half of the profile key is read from the preamble
*above* the header row, so a file that declares no version gets `""` rather than
`0.039` scraped out of a concentration.

**Guards where the loss happened.** A mapping that aims two columns at one field
is refused when saved *and* when loaded — pandas' `rename` silently kept only
the last. Suggestions are de-duplicated, so the three columns matching the RT
pattern no longer all become `observed_rt`.

**One definition of the reported concentration.** `models.reported_conc()`
serves `build_summary` and `injection_store`, which previously chose opposite
columns. It does not fall back past a verdict either: `br-PFHxS` said
"Not Detected" with a 0.000188 raw reading, and falling through resurrected a
number the instrument declined to report.

**Results bind on ClientSampleID.** An injection name *is* the client's name for
the sample. The connector already searched that index; it was never called with
it. Analyte names route through `analyte_reference.COMPOUND_NAME_TO_KEYWORD`,
which has always held the display-name → keyword mapping.

**API failures surface.** senaite.jsonapi answers a refused operation with HTTP
200 and `success: false`, so `raise_for_status()` alone let failures pass — that
is how a delete the workflow rejected got logged as five superseded attachments.

**Batches are found wherever they live.** `senaite.pfas.batch_ref` resolves a
Batch by id; five call sites indexed `portal["batches"]` and could not see a
client-owned batch. The Run Builder reported that as "Batch has no method — fill
its extraction log first".

Also confirmed: 0 of 1254 rows lack a timestamp (was 1254); 72 BLoQ / 17 ALoQ /
9 N.D. preserved into `injection_results`; profile resolves with no
hand-registered stopgap; the worksheet holds one byte-identical report PDF.

**Result coverage, precisely.** All 192 summary rows reach a SENAITE Analysis —
6 sample injections × 32 analytes, with `FEED-0002 PFOS = 1.55387076762`. That
is 192 of the batch's **288** analyses; the other 96 belong to the MB, LFSM and
LFSMD samples, which `build_summary` does not emit rows for (it covers
`Sample`-classified injections only). Those three samples still carry no
results — a gap in the summary builder, not in the linkage.

**Two paths verified only in part.** The de-duplication of suggested mappings
was checked on all four vendor profiles (`waters`, `agilent`, `sciex` exercise
the regex guesser; `native` takes the exact-match branch) and produces no
duplicate targets on any, with the guard correctly identifying the legacy bad
map. The attachment fix was proven on the report PDF; the extraction-log JSON
upload uses the same call but was never exercised, because
`extraction_log_path` was None in every run.

**Timestamps changed a QC fact.** With acquisition times parsing, the CCV
resolves to **three** injections (19:03, 21:08, 22:53) instead of one — every
repeat of an injection name had been collapsing into a single group, so two of
the three bracketing CCVs were invisible.

**Regression:** demo batches `B-002`…`B-006` and `example-batch-fda32` retain
their logbook annotations; the five pre-existing prepared standards keep their
statuses; the three reagent lots matched by catalogue number were not written
to. Stray batches and empty attachments from the pre-fix runs removed. Eleven
key pages return 200 with no traceback.

## Still open — and why they were left

**Not input, and one needs your decision.**

- **B18 `recovery_tiers` is unseeded** — the FDA 40–140% no-labeled-standard
  recovery tier does not exist anywhere. The same concept is represented three
  times (`qc_acceptance.tiers`, `recovery_tiers`,
  `analyte_reference.no_labeled`); which one survives is a §1.3 call for you,
  not something to guess.
- **B5 ion-ratio check** — still compares `Response Ratio` against the mean over
  all 10 calibration levels: 658 flags where a correct check gives 23 and the
  instrument's own verdict says 140. Now unblocked, because
  `expected_ion_ratios` is finally mappable.
- **B6 / B7 gates** — traceability and QC Summary still cannot pass: the CoC has
  no `batch_id` field, the guided-extraction stub drops the reagents it
  collected, and nothing writes `qc_results`.
- **B15 EDD** — re-run after B8, and it was *starved*, not broken: 125 of 288
  rows now carry a concentration (0 before). Still open: nothing blocks an
  export with 163 empty rows, the EGAD sample type falls back to a hardcoded
  `GW`, and `LAB_QUALIFIER` only ever emits `U` — the BLoQ / ALoQ verdicts now
  preserved on import do not reach it.
- **B17** prepared standards expire retroactively — needs a ruling on whether
  expiry is judged at time of use.
- **B19** empty-gate messages misdirect the analyst.

**Two things this round surfaced that are worth a decision:**

- **The LIMS now generates names its own validator rejects — and the names are
  right.** Before this round, `INJECTION_PATTERNS` rejected 8 of 20 *instrument*
  names. It now rejects 26 of 27 *LIMS-generated* names, including the sample
  names that provably bind and round-trip. The validator is the part that is
  wrong, and it is a hardcoded Python constant encoding one lab's convention
  (§1.1). Making it configurable is a design choice, so it is flagged rather
  than guessed — but it is more urgent than it looks, because the system is now
  warning about its own correct output.
- **The worklist proposes 27 injections for a 20-injection run.** MB, LFSM and
  LFSMD appear twice — once as batch samples and again as template-generated QC.
  The run template and the sample list overlap, and whether the template should
  suppress tokens already present as samples is your call.
